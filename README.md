# A&A's Bookshop Stationery

A forest-green, cream and gold storefront for books and stationery, with a private owner area for managing the catalogue, orders and customers. Prices are in Kenyan shillings (KSh).

## Features

- Storefront: home, product catalogue, category browsing, product details, cart, checkout and order history.
- Cart and saved order references persist in the browser with `localStorage`.
- Permanent SQLite database locally and Neon PostgreSQL on Vercel, with server-calculated order prices and totals; browser-sent prices are never trusted.
- Owner-only admin at `/admin`: dashboard stats, product CRUD, category add/edit/reorder, image uploads, order status updates and customer order history.
- Signed, HTTP-only admin session cookies, password hashing, login rate limiting, same-origin API checks and security headers.
- Responsive layouts for phones, tablets and desktops.

Payments are **not** integrated with M-Pesa or any gateway yet. Checkout currently records the customer's preferred payment method (for example, "M-Pesa on Delivery") and the owner manages fulfilment from the admin area.

## Requirements

- Node.js 24 or newer (local development uses the built-in `node:sqlite` module).
- npm.

## Local development

```bash
npm install
cp .env.example .env.local
npm run setup:admin -- owner@example.com your-strong-password
npm run dev
```

Open `http://localhost:3000`. The setup script writes `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH` and `AUTH_SECRET` into `.env.local`. Keep this file secret; it is gitignored.

Then visit `http://localhost:3000/admin/login` and sign in with the credentials you chose.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `ADMIN_EMAIL` | Owner login email. |
| `ADMIN_PASSWORD_HASH` | Scrypt hash generated by `npm run setup:admin`. |
| `AUTH_SECRET` | 32+ character secret used to sign session tokens. |
| `AAS_DATABASE_PATH` | Local SQLite file location. Defaults to `./data/shop.sqlite`; ignored when `DATABASE_URL` is set. |
| `DATABASE_URL` | Neon pooled PostgreSQL connection string used by the running app, including on Vercel. |
| `DIRECT_URL` | Neon direct connection string used by migration and verification scripts only. |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob token for persistent product images. Without it, local development falls back to `public/uploads/`. |
| `TRUST_PROXY_HEADERS` | Set to `1` only behind a trusted reverse proxy that sets `X-Forwarded-*` headers. |

## Data storage

- The local SQLite database is created and seeded automatically from the original 8-product catalogue on first run. No product prices or stock levels were invented.
- Schema versioning is stored in the `meta` table. Once a database has been seeded, deleting all products will not re-seed the demo catalogue; delete the database file itself only when you intentionally want a fresh shop.
- Local development uses `data/shop.sqlite` and `public/uploads/` unless `DATABASE_URL` and `BLOB_READ_WRITE_TOKEN` are set.
- On Vercel, `DATABASE_URL` switches the app to Neon PostgreSQL and `BLOB_READ_WRITE_TOKEN` stores uploaded images in Vercel Blob. The local SQLite file and `public/uploads/` are not persistent on Vercel.
- Migration scripts are non-destructive: they refuse to write into a Neon database that already contains rows and never delete local data.

## Commands

```bash
npm run dev          # development server
npm run build        # production build
npm start            # production server (after build)
npm run lint         # ESLint
npm run typecheck    # TypeScript
npm test             # Node test suite (cart, database, auth)
npm run setup:admin -- <email> <password>
npm run db:test        # check Neon connection (after adding DIRECT_URL)
npm run db:migrate     # copy local SQLite rows into an empty Neon database
npm run db:verify      # compare local and Neon row counts/data
npm run db:uploads     # copy local product images to Vercel Blob and update Neon URLs
```

## Deployment (Vercel + Neon + Vercel Blob)

1. Create a Neon PostgreSQL database and a Vercel Blob store.
2. Add `DATABASE_URL` (pooled), `DIRECT_URL` (direct), `BLOB_READ_WRITE_TOKEN`, `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH` and `AUTH_SECRET` to both `.env.local` and the Vercel project environment.
3. Run `npm run db:test`, then `npm run db:migrate`, then `npm run db:verify`.
4. Run `npm run db:uploads` to move existing product images to Vercel Blob.
5. Deploy a preview branch first, test the storefront/admin flows, then switch production only after approval.
6. Keep `.env.local`, `data/` and `public/uploads/` out of version control. Back up Neon and Vercel Blob separately.

## Deployment (self-hosted Node/VPS)

1. Install Node.js 24+ and place the project on the server.
2. Run `npm ci`.
3. Create `.env.local` from `.env.example` and run `npm run setup:admin -- <email> <password>` with a strong, unique password.
4. Point `AAS_DATABASE_PATH` at a persistent path, for example `/var/www/aas-shop/data/shop.sqlite`.
5. Run `npm run build`, then `npm start` behind a reverse proxy such as Nginx with HTTPS. Set `TRUST_PROXY_HEADERS=1` only if that proxy reliably sets `X-Forwarded-*` headers.
6. Ensure the process user can write to the database directory and `public/uploads/`.
7. Keep `.env.local`, `data/` and uploaded images out of version control; back up the database and uploads regularly.

Do not deploy with temporary test credentials or a test database.

## Project layout

- `app/(shop)/` – public storefront pages.
- `app/admin/` – protected owner area and server actions.
- `app/api/` – order creation, order lookup and image upload APIs.
- `app/components/` – shared UI and cart provider.
- `lib/` – database, catalogue, order, auth and security helpers.
- `scripts/setup-admin.mjs` – owner credential generator.
- `scripts/migrate-sqlite-to-neon.mjs`, `scripts/verify-neon-migration.mjs` and `scripts/migrate-uploads-to-blob.mjs` – non-destructive deployment helpers.
- `tests/` – automated tests.
